# 贾维斯管家 · 日常维护指南

> 学会这些，你就能自己维护贾维斯，不依赖任何人。

---

## 💾 一、数据备份（最重要的事！）

### 1. 数据存在哪？

贾维斯的**所有数据**都在这 3 个地方：

| 位置 | 内容 | 重要性 |
|---|---|---|
| `backend/data/kizuna.sqlite3` | 聊天记录 + 人格 + 记忆元数据 + 提醒 + 工具日志 | ⭐⭐⭐⭐⭐ |
| `backend/data/chroma_db/` | 记忆的向量索引（用于语义搜索） | ⭐⭐⭐ |
| `backend/.env` | 你的 API Key 和模型配置 | ⭐⭐⭐ |

### 2. 怎么备份？

#### 方式 A：手动复制（最简单）
整个 `backend/data/` 文件夹 **复制粘贴**到网盘 / U 盘 / 另一台机器就行。
建议每周备份一次。

#### 方式 B：命令行（可写进计划任务自动备份）
```bash
# Linux / Mac：打包成压缩包
cd backend
tar -czf "jarvis-backup-$(date +%Y%m%d).tar.gz" data/ .env

# Windows：打包成 zip（PowerShell）
Compress-Archive -Path data,.env -DestinationPath ("jarvis-backup-" + (Get-Date -Format "yyyyMMdd") + ".zip")
```

#### 方式 C：git 私有仓库（进阶）
把整个项目放进 GitHub 私有仓库（注意要把 `data/` 和 `.env` 也加进去，**不要用公开仓库！**）。

### 3. 怎么恢复备份？

把备份的 `data/` 文件夹和 `.env` 文件 **复制覆盖** 到 `backend/` 目录下，重启贾维斯即可。

## 🔄 二、更新 / 升级贾维斯

### 情况 1：只更新依赖（最常见）

当 Python 有新版本的库、或者大模型 SDK 更新了：
```bash
cd backend
pip install -U -r requirements.txt

# 前端同理
cd ../frontend
npm update
npm run build
```

### 情况 2：贾维斯代码升级（比如你从 GitHub 拉了新版）

**升级前先备份 data/！**（不备份=可能丢所有聊天记录）

```bash
# 1. 备份（养成习惯！）
cp -r backend/data backend/data.bak-$(date +%Y%m%d)

# 2. 拉新代码（如果用了 git）
git pull

# 3. 安装新依赖
cd backend && pip install -r requirements.txt
cd ../frontend && npm install && npm run build

# 4. 启动看看是否正常
cd ../backend && python app.py
```

### 情况 3：数据库迁移（新增字段/表时）

项目用的是 **SQLite + SQLAlchemy**，每次启动会自动 `create_all()`（加新表），
但**已存在的表不会自动加字段**。遇到报错说"找不到某某列"时：

方式 A（简单粗暴，数据少时）：
1. 先把 `data/kizuna.sqlite3` 备份一份
2. 删掉它，重启贾维斯自动重建
3. 再用「数据档案」手动把重要记忆加回去（不多的话）

方式 B（保留数据，进阶）：用 **Alembic** 做数据库迁移（可以查一下 Flask/Alembic 教程，流程一样）。

## 🧐 三、日志和排错

### 1. 日志在哪看？

贾维斯把日志**直接打到控制台**（也就是你启动 `python app.py` 的那个黑色/白色窗口）。
如果服务是后台运行的，启动时要重定向到文件：

```bash
# Linux / Mac：后台跑，日志写 jarvis.log
nohup python app.py > jarvis.log 2>&1 &
tail -f jarvis.log   # 实时看日志
```

```powershell
# Windows PowerShell：后台跑
Start-Process python -ArgumentList "app.py" -RedirectStandardOutput jarvis.log -RedirectStandardError jarvis-err.log
Get-Content jarvis.log -Wait   # 实时看
```

### 2. 常见报错 · 自助排查表

| 报错现象 | 原因 | 解决办法 |
|---|---|---|
| `LLM 初始化失败: No API key provided` | 没填 API Key 或 .env 读不到 | 去「LLM 接入」页面重新填一遍保存 |
| `ChatLLM 请求失败: 401 Unauthorized` | Key 错了、过期了、或者余额没了 | 去供应商控制台检查 Key 和余额 |
| `ChatLLM 请求超时` | 网络不通 / 墙 / 海外模型连不上 | OpenAI 这类国内需要代理，在 .env 加 `HTTP_PROXY=http://127.0.0.1:7890` |
| `Database is locked` | SQLite 被多进程同时写了 | 关了所有 Python 进程再重新启动 |
| 前端白屏 / `ChunkLoadError` | 前端构建产物没生成或过期 | `cd frontend && rm -rf dist node_modules && npm install && npm run build` |
| `ModuleNotFoundError: No module named xxx` | 没装依赖或装错版本了 | `pip install -r backend/requirements.txt` |
| 工具不被调用（问天气说自己猜的） | LLM 能力弱，没理解 system prompt | 1. 换更强的模型（如 GLM-4 / Claude 3）2. 用 `/weather` 快捷命令绕过 LLM 规划 |
| 早上 7:30 没收到早安问候 | APScheduler 没启动 / 电脑关了 | 1. 控制台日志搜 `APScheduler 未启动` 看原因 2. 电脑要一直开着才行（可以用树莓派/云服务器 24h 跑） |

### 3. 如何判断某个功能坏了？

**用「工具矩阵」页的「手动执行」逐个测试：**
1. 打开 `/tools` 页面
2. 找到 `sys_info` → 展开 ▶ 手动执行
3. 如果成功了 → 后端 + 工具链路正常
4. 再测 `weather` → 如果报错 → 网络连不上 wttr.in（可能是防火墙）
5. 每个工具单独测，就能定位问题在哪

## ⚡ 四、性能调优

### 1. 贾维斯变慢了？一般是这些原因

| 瓶颈 | 症状 | 优化 |
|---|---|---|
| 大模型 API 慢 | 每次要等 10+ 秒才回复 | 换一个就近的供应商（国内用智谱/通义/DeepSeek） |
| 记忆向量库慢 | 第一次搜索卡几秒 | 正常，ChromaDB 冷启动要加载索引；或者减少 `top_k`（在 `memory.py` 改） |
| 聊天历史太多 | 滑动卡、LLM 上下文字数超标 | 定期备份 + 清空旧消息：`DELETE FROM messages WHERE created_at < '2025-01-01'` |
| 磁盘占满 | data 目录越来越大 | 1. `VACUUM;` 一下 SQLite（SQLite 专家模式命令） 2. 清理 `tool_logs` 表的老记录 |

### 2. 让贾维斯 24 小时运行（推荐）

#### 方案 A：家里的树莓派 / 旧笔记本（最省）
只要不断电、能联网就能跑。树莓派 4 2G 就够了。

#### 方案 B：云服务器（最稳定）
阿里云 / 腾讯云 / AWS 最便宜的轻量服务器（约 30~50 元/月）即可。

#### 方案 C：进程守护（服务器上必做）
用 `systemd`（Linux）把贾维斯注册成服务，崩溃自动重启：

```ini
# /etc/systemd/system/jarvis.service
[Unit]
Description=JARVIS AI Butler
After=network.target

[Service]
Type=simple
User=your-user
WorkingDirectory=/home/your-user/kizuna-ai/backend
ExecStart=/usr/bin/python3 app.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

然后：
```bash
sudo systemctl daemon-reload
sudo systemctl enable jarvis --now
sudo systemctl status jarvis   # 看运行状态
sudo journalctl -u jarvis -f   # 实时看日志
```

## 🔐 五、安全维护

1. **API Key 保护**
   - `.env` 文件权限设为只有你能读（Linux: `chmod 600 .env`）
   - 绝对不要把 `.env` 放进公开的 GitHub 仓库！（项目里的 `.gitignore` 已经忽略了，放心）

2. **外网访问**
   - 默认贾维斯只监听 `127.0.0.1`（本机访问）
   - 想在外网用：用 Cloudflare Tunnel / Tailscale / frp 等内网穿透，**不要直接改 0.0.0.0 裸奔**
   - 或者给 `/api/*` 加 Basic Auth（在 `app.py` 的中间件里加，大约 10 行代码，查 FastAPI Basic Auth 教程）

3. **定期检查**
   - 每月看一次「工具矩阵」→「工具调用日志」，有没有异常调用
   - 每月看一次供应商的 token 用量账单，有没有异常暴涨（防止 Key 泄露）
